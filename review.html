cut.lua

CRITICAL 
function HandSaw:new(file, output_location)
    setmetatable({}, self)  -- результат выброшен!
    self.__index = self
    self.file = file
    ...
    return self  -- возвращается прототип HandSaw, а не новый объект
end

setmetatable({}, self) создаёт новую таблицу и назначает ей метатаблицу, но результат никуда не сохраняется. Дальше функция модифицирует self (который является таблицей-прототипом HandSaw) и возвращает его же. Все «экземпляры» HandSaw — одна и та же таблица. При обработке папки каждый следующий файл затирает данные предыдущего.

Правильный паттерн:

function HandSaw:new(file, output_location)
    local o = {}
    setmetatable(o, self)
    self.__index = self
    o.file = file
    ...
    return o
end
✅ RESOLVED Регрессия: o.scaled_height = self.height

Строка закомментирована (-- o.scaled_height = o.height). Проблема устранена.

subcliper.lua

CRITICAL 
local Regions = {}

Index = 1  -- нет local! Переменная стала глобальной

Случайно пропущенный local. Поскольку mpv выполняет все скрипты в одном Lua-состоянии, глобальная Index может конфликтовать с другими плагинами или быть перезаписана. Нужно: local Index = 1.

HIGH 
function Loop:new(a, b)
    self = {}             -- перезаписывает неявный параметр self
    setmetatable({}, self) -- результат выброшен
    self.a = a
    self.b = b
    return self              -- возвращает пустую таблицу без метатаблицы
end

self = {} создаёт новый локальный self, затеняя параметр (которым при вызове Loop:new(...) является таблица Loop). setmetatable({}, self) создаёт таблицу с метатаблицей, но результат теряется. Сейчас это работает только потому, что у экземпляров Loop нет методов — они используются как простые контейнеры {a, b}. Но код вводит в заблуждение. Правильный вариант: 

function Loop:new(a, b)
    return setmetatable({ a = a, b = b }, { __index = self })
end
🆕 NEW Лог-файл не закрывается на пути ошибок в process_folder

Batch:new() открывает o.log и делает io.output(o.log). В process_folder() вызов self.log:close() происходит только на пути успеха ("success!"). Если обработка прерывается досрочно (done == nil или done == false), дескриптор лога остаётся открытым. На уровне одного запуска process.lua это не критично (GC закроет), но при многократных вызовах возможна утечка. Кроме того, io.output(o.log) меняет глобальный поток вывода для всего Lua-состояния — побочный эффект, который может повлиять на другие модули.

Рекомендация: использовать o.log:write(...) вместо io.output() + io.write(), и закрывать лог в finally-подобном блоке или во всех точках возврата.

batch.lua

HIGH 
function Batch:new(output_folder)
    self.output_folder = output_folder
    ...
    return self  -- self === Batch (прототип)
end

Здесь нет даже попытки создать новую таблицу. Вызов batch:new(save_to) модифицирует таблицу-прототип Batch и возвращает её же. При однократном использовании (как в process.lua) это работает, но повторный вызов :new() перезапишет состояние. Нужно создавать local o = {}; setmetatable(o, self); self.__index = self.

MEDIUM 
if status.code == 255 then
    io.write("most probably incomplete and will be deleted:\n" ...)
    os.remove(clip.clip_path)
end

Код 255 не является стандартным для «неполного файла». ffmpeg возвращает код ошибки в зависимости от причины прерывания. Лучше проверять реальный размер выходного файла или длительность через ffprobe.

LOW

Исходные файлы перемещаются в поддиректорию __READY. Если операция обрезания упадёт на середине, часть файлов уже будет перемещена, а часть — нет. Состояние становится неконсистентным. Надёжнее перемещать только после полного успеха, либо вести лог отдельно.

function M.strip_path(path_to_file)
    local path = path_to_file:match("^/?(.+)/")   -- требует хотя бы один /
    local name = path_to_file:match(".+/(.+)%..+$")
    local type = path_to_file:match(".+%.(.+)$")
    ...
end

Для /video.mp4 или video.mp4 ни один паттерн не сработает — все три переменные будут nil. Стоит добавить fallback: если path не найден — path = ""; если name не найден — поиск без директории.

MEDIUM

Трюк с переименованием файла в самого себя работает на большинстве Unix-систем (rename(2) с одинаковыми путями — no-op), но теоретически может обновить mtime на некоторых ФС. Проще и надёжнее: 

function M.exists(file)
    local f = io.open(file, "r")
    if f then f:close(); return true end
    return false
end

Если у файла нет расширения, ext будет nil, и конкатенация даст "filename.nil". Нужно: local full_name = ext and (name .. "." .. ext) or name.

🎯 Общие замечания

STYLE

В проекте три реализации конструкторов — и все три разные (и две с ошибками). Выберите один паттерн и придерживайтесь его: 

-- Рекомендуемый паттерн для Lua
local MyClass = {}

function MyClass:new(...)
    local o = {}
    setmetatable(o, self)
    self.__index = self
    -- инициализация полей o
    return o
end
STYLE

CamelCase (HandSaw, Regions), snake_case (validate_region, set_loop), UPPER_CASE (FFMPEG, SPACE, KEEP). Стоит выбрать один стиль. Типичные конвенции Lua: snake_case для функций и переменных, PascalCase для классов-таблиц.

STYLE

Переменные SPACE, COMMA, INPUT объявлены как локальные модуля, но используются только внутри методов HandSaw. Их можно сделать полями класса или инлайнить, чтобы уменьшить когнитивную нагрузку при чтении.
